## Source Reconciliation

The public docs were checked against the tracked CLI and parser source for:

- CLI arguments and defaults;
- supported transaction and investment discovery keys;
- `.csv`, `.xlsx`, `.xls`, and intentionally unsupported PDF behavior;
- workbook sheet names and validation behavior;
- Frankfurter historical/latest FX handling;
- parser-extension entry points;
- dependency declarations and the undeclared `matplotlib` import; and
- the absence of a dedicated tests directory, CI workflow directory, hosted
  runtime, and license file.

The version changes documentation and navigation only. Current source remains
the higher-priority authority if future behavior changes.

## Privacy Review

The public candidate was scanned for machine-specific absolute paths and
credential-like values. Machine-specific checkout paths found in early
documentation drafts were removed before release.

Representative ignore rules were checked for `.env`, private config, inputs,
outputs, cache, root reports, actual files under `finance/private/`, and local
`.obsidian/` state. The tracked `finance/private/README.md` contains handling
instructions only; actual snapshot JSON and Markdown files remain ignored.

No ignored private file content was opened to prepare this report.

Additional local checks validate the finance example against the Draft 2020-12
schema, confirm that its financial fields remain null-valued, resolve relative
Markdown links, resolve machine-index paths, scan the public candidate for
absolute paths and credential-like values, verify representative ignore rules,
and run `git diff --check`.

The `jsonschema` validator used for this release check was installed in a
temporary directory outside the repository because it is a validation tool,
not an application dependency. `requirements.txt` was not changed.

All listed privacy-safe checks passed for the final candidate. Normal
working-copy LF/CRLF conversion warnings are environment notices, not
`git diff --check` errors.

## Checks Intentionally Not Run

A full workbook build was not run. It would read private `input/` data and
rewrite ignored `output/`, `cache/`, and `reports/` artifacts, while this
version does not change runtime code.

No live hosted application check exists because this repository is a local CLI
and has no deployment workflow or runtime endpoint.

## Release And Publication Boundary

The v0.0.2 documentation can be committed and pushed to the repository's
`main` branch. A successful Git push proves publication of that exact commit to
the remote branch; it does not prove a hosted deployment, Git tag, GitHub
Release, workflow run, or workbook build. Those are separate actions and
evidence classes.
