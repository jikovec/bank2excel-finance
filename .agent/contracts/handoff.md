# Handoff contract

Lead with the achieved outcome and remaining required action. Include only
material evidence: baseline/target, changed files, durable decisions, check
commands and categories, blockers, Git/PR/merge identity, and any actual release,
deployment, publication, or observed live state. Link artifacts and references.

Record intentional gate bypasses and external protections encountered when
relevant. State the exact missing input or authority and its source. Separate
out-of-scope follow-up from unfinished required work. Avoid empty checklists.

Use `docs/current-state.md` for durable repository shape and `docs/decisions.md`
for accepted decisions. Use a dated note under `handoffs/` and link its index
for material temporary limitations. A prior handoff is historical evidence,
not proof of current state. Follow [security model](../../docs/security-model.md):
no private financial contents, secret values, or machine-specific paths in
tracked handoffs or public work-management records.
